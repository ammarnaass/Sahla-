# سهلة · PRD ومواصفة المحرك: استوديو البحوث المدرسية ومذكرات التخرج

**النسخة 1.0 · الجزائر · يكمّل: PRD البحوث المدرسية، ونظام التوجيه، ومحرك الـ API والمهارات**

> **ملاحظة منهجية:** قواعد المذكرات (الغلاف، الترتيب، الحجم، أسلوب التوثيق) تختلف بين الجامعات والكليات والأقسام ومراكز التكوين. لا تُكتب من الذاكرة، بل تُحمَّل في «ملف مؤسسة» من دليل المذكرة الخاص بكل جهة وتُراجَع بشرياً.

---

## 1. الهدف والنطاق

**الهدف:** مساعدة الطالب (عبر صاحب المحل أو مكتب الخدمات) على إنجاز مذكرة تخرج **منظمة ومطابقة لدليل مؤسسته**، مبنية على **معلومات مجموعة من مصادر حقيقية** ومعطيات يقدمها هو، وجاهزة للتعديل والطباعة، وذلك بدل مخرجات عامة غير دقيقة.

**المشكلة الحالية:** المحرك يكتب من ذاكرة النموذج في نداء واحد، فتخرج المذكرة ناقصة أو عامة، دون مصادر مجموعة فعلياً، ولا تتطابق مع الهيكل المطلوب.

**المستويات المشمولة:**

| النوع | أمثلة |
|---|---|
| ليسانس | مذكرة تخرج، تقرير تربص |
| ماستر | مذكرة ماستر (أكاديمي/مهني) |
| تكوين مهني | مذكرة نهاية التكوين (تقني سامٍ، تقني) |
| تقرير تربص / مشروع | تقرير ميداني، مشروع تخرج |

**في النطاق:** تخطيط، بحث، كتابة، تحليل بيانات يقدمها الطالب، توثيق، تنسيق، فحوص الجودة، تصدير DOCX وPDF.
**خارج النطاق:** رسائل الدكتوراه والمقالات المحكّمة، **اختلاق بيانات ميدانية**، والتقديم نيابة عن الطالب في أي منصة.

## 2. المبادئ

1. **لا اختلاق:** لا مراجع وهمية، ولا نتائج استبيانات أو أرقام لم يقدمها الطالب.
2. **الحقيقة من مصدر:** كل معلومة جوهرية مرتبطة بمصدر مُسترجع فعلاً.
3. **الهيكل من ملف المؤسسة:** لا قالب واحد للجميع.
4. **الأرقام بالأدوات:** التحليل الإحصائي يُحسب بالكود وليس بالنموذج.
5. **الطول عبر التقسيم:** فصل بعد فصل، لا نداء واحد.
6. **الطالب يقود:** يعتمد الخطة والمصادر ويعدّل، والنظام أداة مساعدة.
7. **شفافية:** تقرير جودة ومصادر يرافق كل مذكرة.

## 3. النزاهة الأكاديمية والاستعمال المسؤول

- تنبيه صريح في الشروط: الوثيقة مسودة مساعدة، والطالب مسؤول عن مراجعتها وملاءمتها لمؤسسته ولقواعد النزاهة فيها.
- **الجزء التطبيقي:** لا يُولَّد من عدم. يرفع الطالب بياناته (Excel/CSV) أو يصف حالة حقيقية، ويقتصر النظام على التحليل والصياغة، وإلا اقتصر الفصل على إطار منهجي وأدوات جمع.
- **الاستبيان:** يساعد النظام في بناء الأسئلة ومقاييس الصدق والثبات، ولا يختلق إجابات.
- **فحص التشابه:** تقدير داخلي مبدئي (تكرار داخل المذكرة وتطابق نصي مع المصادر المسترجعة)، مع تنبيه أنه لا يغني عن برامج الجامعة.
- لا نسخ حرفي لفقرات المصادر، والاقتباس القصير فقط مع توثيقه.
- سياسة خصوصية: بيانات الطالب والمؤسسة تُحذف بعد المدة المحددة (قانون 18-07).

## 4. المستخدم ومساره

### 4.1 الاستمارة الموجَّهة (Intake)

| الخطوة | الحقول |
|---|---|
| 1. المؤسسة | الجامعة/المعهد، الكلية، القسم، الطور (ليسانس/ماستر/تكوين)، التخصص، اللغة |
| 2. ملف المؤسسة | اختيار ملف جاهز، أو رفع «دليل المذكرة» (PDF) لاستخراج القواعد |
| 3. الموضوع | العنوان أو الفكرة، والإشكالية إن وُجدت |
| 4. النوع | نظرية، ميدانية، دراسة حالة، تقرير تربص |
| 5. الحجم والتوثيق | عدد الصفحات المطلوب، أسلوب التوثيق (APA/ISO 690/غيره) |
| 6. المنهج والبيانات | منهج مقترح، وهل توجد بيانات؟ (رفع ملف أو إدخال) |
| 7. الأستاذ | عناصر إلزامية من المشرف، ومراجع يفرضها |
| 8. الغلاف | البيانات الشخصية والمشرف ولجنة المناقشة والسنة الجامعية |
| 9. المراجعة | بطاقة المواصفة بالتكلفة التقديرية |

### 4.2 مراحل العمل للمستخدم

`خطة ← اعتماد ← مصادر ← اعتماد ← كتابة الفصول ← مراجعة ← تحليل ← تجميع ← تصدير`

يمكن للمستخدم التوقف والعودة، وتعديل أي مرحلة، وإعادة توليد فصل واحد دون المساس ببقية المذكرة.

## 5. ملف المؤسسة (Institution Profile)

يحدد كل ما يتغير بين الجهات:

```yaml
profile_id: UNIV-EXAMPLE-MASTER@2026.1
language: ar
cover:
  header: ["الجمهورية الجزائرية الديمقراطية الشعبية",
           "وزارة التعليم العالي والبحث العلمي"]
  fields: [university, faculty, department, degree, specialty,
           title, student, supervisor, jury, academic_year]
front_matter: [dedication, acknowledgments, abstract_ar, abstract_fr,
               abstract_en, toc, list_tables, list_figures, abbreviations]
structure:
  general_intro:
    required: [context, problem, hypotheses, importance, objectives,
               reasons_for_choice, methodology, scope, previous_studies, outline]
  chapters: { min: 3, max: 5, theoretical_first: true, applied_required: true }
  general_conclusion: [findings, recommendations, future_work]
  back_matter: [references, appendices]
pages: { min: 60, max: 120 }
citation: { style: "APA7", in_text: "author-year", numbering: "arabic" }
format:
  paper: A4
  margins_mm: { top: 25, bottom: 25, start: 30, end: 20 }
  font: { family: "Traditional Arabic", body_pt: 14, heading_pt: [18, 16, 14], line_spacing: 1.5 }
  page_numbers: { front: "abjad", body: "arabic" }
```

> القيم أمثلة توضيحية؛ تُملأ من دليل المؤسسة الفعلي.

**استخراج القواعد من دليل المذكرة:** يرفع المستخدم دليل جهته، فتقرأه مهارة `guide-extractor` وتقترح ملفاً يعتمده المستخدم أو مشرف المحتوى قبل الاستعمال.

## 6. معمارية المحرك

```
[Intake] → [Spec] → [Planner] → (اعتماد)
                         │
        ┌────────────────┴───────────────────────────┐
   لكل فصل (بالتوازي المحدود):
   [Researcher] → [Source Vetter] → [Fact Sheet] → (اعتماد المصادر)
                         │
                  [Chapter Writer] → [Chapter Validators] → [Repair]
                         │
   البيانات: [Data Ingest] → [Stats Engine (كود)] → [Results Narrator]
                         │
                [Assembler] → [Global Validators] → [Formatter DOCX/PDF]
                         │
                     [Quality Report]
```

كل خطوة مهمة (Job) في طابور Redis، وتُنفَّذ في Worker وليس في طلب HTTP، مع حفظ الحالة بعد كل خطوة لإمكان الاستئناف.

## 7. المهارات (Skills)

### 7.1 `thesis-planner`: الخطة

| البند | التفاصيل |
|---|---|
| المدخلات | Spec، ملف المؤسسة، الموضوع |
| المخرجات | عنوان محسّن، إشكالية، أسئلة فرعية، فرضيات، منهج، فصول ومباحث بوزن صفحات |
| القواعد | الخطة تطابق `structure` في ملف المؤسسة، والفصل التطبيقي لا يُخطَّط إلا إذا وُجدت بيانات أو منهج واضح لجمعها، ولا تُدرج عناوين متكررة |
| الاعتماد | يعدّلها المستخدم قبل المتابعة |

### 7.2 `researcher`: البحث وجمع الحقائق (لكل فصل)

| البند | التفاصيل |
|---|---|
| الأدوات | `google_search` و`url_context` في Gemini، أو مزوّد بحث آخر عبر الطبقة الموحدة |
| المدخلات | عنوان الفصل ونقاطه، لغات البحث (عربي، فرنسي، إنجليزي)، قائمة النطاقات المفضلة |
| المخرجات | `fact_sheet`: قائمة حقائق، لكل حقيقة: `claim`, `evidence_snippet_summary`, `source_id`, `confidence` |
| القواعد | عدة استعلامات بصيغ مختلفة؛ تُقرأ الصفحات المرشحة؛ تُلخص ولا تُنسخ؛ ما لم يوجد يُسجَّل «فجوة معرفية» ولا يُملأ من الذاكرة |
| ملاحظة تقنية | تُفصل مرحلة البحث (بأدوات) عن مرحلة الكتابة (بمخطط)، لأن الجمع بين المخرجات المنظمة والبحث قد يُفقد بيانات الإحالة إلى المصادر |

**المصادر المفضلة (قائمة تُدار من لوحة الإدارة):** منصة المجلات العلمية الجزائرية (ASJP)، مستودعات الجامعات الجزائرية، مستودعات الرسائل المفتوحة، Google Scholar، Cairn، مواقع الوزارات والهيئات الرسمية (ONS، بنك الجزائر، وزارات القطاع)، المنظمات الدولية (البنك الدولي، الأمم المتحدة)، ودور نشر أكاديمية.

### 7.3 `source-vetter`: تقييم المصادر

| الفحص | التفاصيل |
|---|---|
| التحقق من الوجود | طلب فعلي للرابط (HEAD/GET)، وللدوي (DOI) عبر Crossref أو OpenAlex |
| بيانات المرجع | استخراج المؤلف، العنوان، السنة، الناشر/المجلة، الرابط، وتاريخ الاطلاع |
| المصداقية | درجة (0–1): نوع المصدر، الجهة، الحداثة، الاستشهاد، وجود مؤلف |
| الإقصاء | مواقع بلا مؤلف أو منتديات أو محتوى مولّد/مجهول، إلا للضرورة مع وسم «ضعيف» |
| الفهرس | `sources` بمعرّف ثابت `S1…Sn` يُستعمل في الاستشهاد |

**واجهة المصادر:** يرى المستخدم المصادر المقترحة لكل فصل، ويحذف أو يضيف (برابط أو DOI أو رفع PDF)، ثم يعتمدها.

### 7.4 `chapter-writer`: كتابة الفصل

| البند | التفاصيل |
|---|---|
| المدخلات | خطة الفصل، fact_sheet المعتمد، ملخص الفصول السابقة، ملف المؤسسة، اللغة |
| المخرجات | بنية JSON: مباحث ← فقرات، لكل فقرة `text` و`cites:[S#]` |
| القواعد | الكتابة من الحقائق فقط؛ كل ادعاء جوهري ينتهي بإحالة؛ ما يُعدّ رأياً يُصاغ كاستنتاج الباحث؛ أسلوب أكاديمي ومصطلحات التخصص؛ لا تكرار مع فصول سابقة؛ جدول أو شكل حيث يلزم |
| الطول | يُقسَّم الفصل الطويل إلى مباحث تُكتب منفصلة ثم تُدمج |
| النموذج | الأقوى المتاح في الطبقة الموحدة |

### 7.5 `intro-conclusion-writer`: المقدمة والخاتمة

تُكتب **بعد** الفصول، لتنسجم مع ما وُجد فعلاً: المقدمة (الإشكالية، الفرضيات، الأهمية، المنهج، الحدود، الدراسات السابقة، هيكل المذكرة)، والخاتمة (النتائج، التوصيات، الآفاق). وتُراجَع الفرضيات في الخاتمة مقابل نتائج التحليل.

### 7.6 `questionnaire-designer`: تصميم الأداة (إن لزم)

استبيان أو مقابلة أو ملاحظة: محاور، صياغة أسئلة، سلم القياس (ليكرت)، واقتراح حجم العينة، مع تنبيه أخلاقي. لا يُنتج بيانات.

### 7.7 `data-ingest` و`stats-engine`: البيانات والتحليل

| البند | التفاصيل |
|---|---|
| المدخلات | ملف Excel/CSV، وقاموس المتغيرات |
| الفحص | أنواع الأعمدة، القيم المفقودة، القيم الشاذة، التشفير العكسي لبنود الاستبيان |
| الحساب بالكود | وصفي (تكرارات، نسب، متوسطات، انحرافات)، ثبات ألفا كرونباخ، ارتباطات، اختبار t، تباين أحادي، كاي مربع، انحدار بسيط — عبر Python (pandas, SciPy, statsmodels) في Worker معزول |
| المخرجات | جداول وأشكال (PNG/SVG) ونتائج JSON بالقيم الفعلية |
| القاعدة الذهبية | لا يُكتب رقم في النص إلا من نتائج المحرك، ويتحقق مدقق من تطابقه |

### 7.8 `results-narrator`: صياغة النتائج

يحوّل نتائج المحرك إلى نص تحليلي (وصف، دلالة، ربط بالفرضيات) دون تغيير أي رقم، ويرجع الجداول والأشكال المرقّمة.

### 7.9 `abstract-translator`: الملخصات

ملخص بالعربية والفرنسية والإنجليزية (حسب ملف المؤسسة) من نص المذكرة النهائي، مع الكلمات المفتاحية.

### 7.10 `citation-formatter`: التوثيق

تنسيق المراجع بحسب الأسلوب المطلوب (APA 7 وISO 690 وغيرهما) من بيانات `sources` المتحقق منها، وترتيبها هجائياً، وتوحيد الاستشهاد داخل النص، والتحقق من أن كل استشهاد له مرجع وكل مرجع مستشهد به.

### 7.11 `assembler` و`formatter`: التجميع والتنسيق

| البند | التفاصيل |
|---|---|
| التجميع | دمج الأقسام بترتيب ملف المؤسسة، وترقيم الفصول والجداول والأشكال |
| الغلاف | من حقول الاستمارة وقالب المؤسسة |
| الفهارس | **فهرس حقيقي** في Word (حقل TOC) وقوائم الجداول والأشكال، لا أرقام صفحات مكتوبة يدوياً |
| التصدير | **DOCX** حقيقي (مكتبة docx) مع RTL وأنماط عناوين وترقيم صفحات بأقسام (مقدمة أبجدية ثم رقمية)، و**PDF** عبر محرك عرض للطباعة |
| الخط والهوامش | من ملف المؤسسة |

## 8. المدققون (Validators)

| الرمز | المدقق | الشدة | الإجراء |
|---|---|---|---|
| T01 | مطابقة الهيكل لملف المؤسسة (عناصر ومباحث) | حرج | إكمال الجزء الناقص |
| T02 | كل استشهاد `S#` له مرجع في الفهرس | حرج | إصلاح أو حذف الادعاء |
| T03 | كل مرجع مستشهد به في النص مرة على الأقل | متوسط | حذف أو تنبيه |
| T04 | كل مصدر تحقق منه (رابط/DOI يعمل) | حرج | استبدال أو سؤال المستخدم |
| T05 | ادعاءات بأرقام/تواريخ/أسماء بلا إحالة | عالٍ | إسناد أو تعميم |
| T06 | تطابق أرقام النص مع نتائج المحرك | حرج | إعادة صياغة من JSON النتائج |
| T07 | طول كل فصل ضمن الحدود | عالٍ | توسيع/تقصير موضعي |
| T08 | التكرار بين الفقرات والفصول | متوسط | إعادة صياغة |
| T09 | اتساق الفرضيات والنتائج والتوصيات | عالٍ | مراجعة الخاتمة |
| T10 | اتساق المصطلحات والاختصارات | متوسط | توحيد |
| T11 | سلامة اللغة والإملاء والأسلوب الأكاديمي | متوسط | تصحيح موضعي |
| T12 | ترقيم الجداول والأشكال والإحالة إليها | متوسط | تصحيح آلي |
| T13 | الغلاف وبياناته مطابقة للملف | حرج | تركيب آلي |
| T14 | الكلمات المحظورة والمحتوى الحساس | حرج | رفض/تعديل |
| T15 | قابلية الاستشهاد: فجوات المعرفة المعلنة (لا ملء من الذاكرة) | عالٍ | تنبيه المستخدم لإضافة مصادر |
| T16 | تقدير التشابه الداخلي والتطابق مع المصادر | متوسط | تقرير + إعادة صياغة |

**قاعدة القبول:** درجة موزونة ≥ 0.85 **ولا خطأ حرج مفتوح**. غير ذلك يُعرض للمستخدم تقرير بالنواقص المطلوب معالجتها بدل تسليم صامت.

## 9. أمثلة مخططات

### 9.1 الخطة

```json
{
  "title": "...",
  "problem": "...",
  "sub_questions": ["...", "..."],
  "hypotheses": ["..."],
  "method": { "type": "descriptive_analytical", "tools": ["questionnaire"], "sample": "..." },
  "chapters": [
    { "id": "c1", "title": "...", "kind": "theoretical", "target_pages": 20,
      "sections": [ { "id": "c1s1", "title": "...", "key_points": ["..."] } ] },
    { "id": "c3", "title": "...", "kind": "applied", "target_pages": 25, "needs_data": true }
  ]
}
```

### 9.2 ورقة الحقائق

```json
{
  "chapter_id": "c1",
  "facts": [
    { "id": "F12", "claim": "...", "source_id": "S4", "confidence": 0.8, "type": "definition" }
  ],
  "gaps": ["لا مصدر موثوق وُجد حول ..."],
  "queries_used": ["...", "..."]
}
```

### 9.3 فقرة مكتوبة

```json
{
  "section_id": "c1s1",
  "paragraphs": [
    { "text": "...", "cites": ["S4", "S7"], "claims": ["F12", "F15"] }
  ]
}
```

### 9.4 قالب تعليمات كاتب الفصل (مختصر)

```text
[ROLE] أنت باحث أكاديمي جزائري في تخصص {specialty} تكتب مذكرة {degree}.
[RULES]
1. اكتب من الحقائق المرفقة فقط. لكل ادعاء جوهري اذكر معرّف المصدر.
2. إن لم تكفِ الحقائق فاكتب "فجوة: ..." ولا تختلق.
3. لا تنسخ عبارات المصادر؛ أعد الصياغة.
4. الأسلوب أكاديمي وواضح بمصطلحات التخصص.
5. التزم الحدود: {min}-{max} كلمة للمبحث، ولا تكرر ما في: {previous_summary}.
[FACTS] {fact_sheet}
[PLAN] {chapter_plan}
[OUTPUT] أرجع JSON وفق المخطط فقط.
```

## 10. الـ API

الأساس `/v1` · `Bearer` · `Idempotency-Key` لكل طلب يخصم نقاطاً.

| الطريقة والمسار | الوصف |
|---|---|
| `GET /institution-profiles` | ملفات المؤسسات المتاحة |
| `POST /institution-profiles/extract` | رفع دليل مذكرة لاستخراج قواعد مقترحة |

### حالات المشروع
`draft → planned → plan_approved → researching → sources_review → writing → analyzing → assembling → quality_review → ready` (مع `failed` و`needs_input`).

### رموز أخطاء مهمة

| الرمز | المعنى |

## 12. التسعير بالنقاط والتكلفة

| الخدمة | الأساس |
|---|---|
| الخطة | مجانية أو رمزية |
| البحث والمصادر | بحسب عدد الفصول |
| كتابة الفصول | بحسب الصفحات المولّدة |
| التحليل الإحصائي | مرة لكل مجموعة بيانات + إعادة محدودة |
| التصدير | مجاني بعد الاستهلاك، مع إعادة تصدير غير محدودة |

- يُحجز الرصيد بالتقدير ويُثبَّت بعد كل مرحلة ناجحة، ويُسترجع جزء المرحلة الفاشلة.
- سقف تكلفة لكل مذكرة، وتنبيه عند اقترابه.
- التخزين المؤقت لنتائج البحث للموضوعات المتكررة.

## 13. المتطلبات غير الوظيفية

- **الاستئناف:** كل مرحلة تُحفظ ويمكن إعادتها دون إعادة السابقة.
- **التوازي المحدود:** فصول بالتوازي ضمن حدود معدل مزوّد الذكاء الاصطناعي، مع إعادة المحاولة التراجعية.
- **الشفافية:** شريط تقدم بمراحل واضحة بالعربية.
- **RTL:** كل المخرجات (DOCX وPDF) سليمة الاتجاه واللغات المختلطة وأرقام الصفحات.
- **الأمان:** عزل تنفيذ كود التحليل (حاوية بلا شبكة وحدود وقت وذاكرة)، وتحقق من الملفات المرفوعة، وحماية من حقن التعليمات في صفحات الويب والملفات.
- **التحديث:** أسماء النماذج والأدوات في الإعدادات، لا في الكود.

## 14. المقاييس ومعايير القبول

### المقاييس

| المقياس | الهدف |
|---|---|
| نسبة المراجع المتحقق منها فعلاً | 100% |
| ادعاءات جوهرية بلا إحالة | < 3% |
| مطابقة الهيكل لملف المؤسسة | ≥ 95% |
| تطابق الأرقام مع نتائج المحرك | 100% |
| رضا المستخدم (تقييم المسودة) | ≥ 4 من 5 |
| نسبة المشاريع المكتملة حتى التصدير | ≥ 60% |
| وقت إنجاز مسودة كاملة (80 صفحة) | أقل من 40 دقيقة معالجة |

### معايير القبول

1. لا يبدأ توليد الفصول قبل اعتماد المستخدم للخطة.
2. كل فصل يعتمد على ورقة حقائق بمصادر مسترجعة فعلاً، ويُظهر فجواته.
3. كل مرجع في القائمة له رابط/DOI عمل أو ملف مرفوع، ومعلّم «متحقق».
4. لا يظهر رقم في الفصول التطبيقية إلا من نتائج محرك التحليل.
5. يحمل الغلاف والترتيب والفهارس شكل ملف المؤسسة المختار، مع فهرس حقيقي في DOCX.
6. تُنتج الملخصات باللغات المطلوبة في ملف المؤسسة.
7. يصدر تقرير جودة بالمدققات T01–T16 وعدد المحاولات وإصدارات الملف والـ Prompts.
8. لا يُسلَّم تصدير نهائي مع خطأ حرج مفتوح؛ يُعرض للمستخدم ما ينقص.
9. يمكن إعادة كتابة فصل واحد دون إعادة بقية المذكرة.
10. تُحذف بيانات الطالب الشخصية والملفات المرفوعة وفق السياسة.

## 16. أسئلة مفتوحة

- هل تبدأ بتخصصين أو ثلاثة (مثل علوم اقتصادية وتسيير، وحقوق، وعلوم اجتماعية) لضبط الجودة؟
- هل نبني مكتبة مراجع داخلية مُراجَعة (مصادر أكاديمية جزائرية موثوقة) لتسريع البحث؟
- هل نسمح بمشاركة المذكرة مع المشرف عبر رابط للتعليق؟
- ما سياسة الاحتفاظ بملفات البيانات (استبيانات الطلبة) بعد التحليل؟
- ما حد المسؤولية والإخلاء في الشروط عن استعمال المسودة داخل المؤسسات؟
